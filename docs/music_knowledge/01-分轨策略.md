# 分轨策略：为什么按"功能"分，而不是按"乐器"分

一句话：**这套链路分的是"职责"，不是"乐器"。** 一轨代表一个听觉功能位，音色是可替换的外衣。

理解这一点之后，"为什么没有吉他"这个问题会自动变成另一个问题：
**"吉他在这里要干哪一层的活？"** —— 如果它干的是和声的活，那它属于 `chords` 层，
只是换个音源；如果它要提供 `chords` 给不了的节奏切分，那才需要新的一层。

---

## 一、分轨到底在分什么

两种分法的差别，用一句话就能看出：

- **按乐器分**：钢琴轨、吉他轨、弦乐轨、贝斯轨、鼓轨……（回答"用了什么"）
- **按功能分**：和声层、低音层、节奏层、装饰层、旋律层、铺底层……（回答"干什么用"）

真实编曲里两种都存在，但目的不同：按乐器分是为了让每个乐器有自己的演奏法和音色，
按功能分是为了让每一层能独立调节、独立替换、独立诊断。

这套工程选功能分法，原因很实际：**它要能被一句话驱动生成。** 如果按乐器分，
"加一把吉他"就意味着新增一整套演奏逻辑；按功能分，"加一把吉他"通常只是给
`chords` 层换个音源 —— 后者不需要改代码。

---

## 二、现在的 8 层，各自干什么

判断某一层是否合理的标准，是**抽掉它会怎样**。如果抽掉之后"少了某种功能"，
而不是"少了一个乐器"，说明这层划分是有意义的。

| 层 | 职责 | 抽掉之后会怎样 | 本工程对应 |
|---|---|---|---|
| `chords` | 说清"现在是什么和弦"，同时承担和声的节奏 | 听不出和声，只剩低音和鼓，像节奏练习 | 按 voice leading 排列，跟随和声节奏分块 |
| `bass` | 和声的根 + 节奏的重心，低频地基 | 整首歌悬空，鼓显得单薄 | 根音折进一个八度窗口，音尾切在换和弦处 |
| `drums` | 时间骨架，决定"这是什么风格" | 没有拍点，其他层显得散 | 三档密度 + 段内渐强 + 过门 + 吊镲 |
| `perc` | 律动的末梢，不占低频的"活" | 律动变老实，短视频里会显呆 | 沙锤 / 铃鼓 / 侧击，按风格换 |
| `arp` | 中高频的"动"，填补留白 | 中高频空一块，副歌不够满 | 和弦音上下行分解，避开旋律音高 |
| `lead` | 听众记住的那条线 | 没有记忆点，听完记不住 | 按和弦音级取音，**音区独占** |
| `counter` | 在主旋律空的地方"回话"，增加纵深 | 主歌略平（它本来只在空档出声，影响最小） | 默认只在 lead 不响时写音、音区压在 lead 之下；`counter_voice: "high"` 改成与主旋律同时响的上方对位 |
| `pad` | 把和声粘住，填满缝隙 | 和声之间有缝，声音发"干" | 长音铺底，有旋律时自动压低并让开音高 |

注意 `lead` 和 `counter` 的关系：一个负责"说"，一个负责"接"。它们是两条**独立声部**，
不是同一条线的两个音色 —— 这是它俩必须分成两轨、而 `chords` 与 `pad` 可以共存的区别。

---

## 三、这么分的好处（每条都能在代码里找到证据）

### 1. 参数正交：改一件事不会牵动另一件

三层各有归属，互不越界：

- `music/core/styles.py` —— 这一层**怎么弹**（律动、音区、连断）
- `music/core/arrange.py` —— 这一段**哪几层出声**、多密、多响
- `config.json` —— **这首歌**用什么调、什么速度、什么和弦

结果就是可以只改一样。工程里有一条测试专门钉住这件事：把副歌换成 playful 风格后，
**主歌一个音符都不变**。如果分轨是按乐器来的，这种正交性很难成立 ——
换风格往往意味着换编制。

### 2. 混音时一个推子对应一个职责

`chords` 太吵，你知道该推哪个推子，而且清楚自己在压"和声"而不是"钢琴"。
按乐器分的话，一个推子背后可能同时承担和声和节奏两种职责，压下去会连带损失。

### 3. 冲突可以被准确定义

工程里体检只查一件事：**同一时刻响同一个音高**。不查"音区是否重叠"——
因为音区重叠完全正常（真实乐器音域本来就大面积重叠）。

这个判断能成立，前提就是按功能分层：同层内部的音区重叠是常态，
跨层（旋律 vs 伴奏）的同音叠置才会磨掉轮廓。上一轮 `pad` 与 `lead` 有 10 处同音，
就是靠这个定义抓出来的。

### 4. 音色免费替换

MIDI 里的"乐器"只是一个 program 号（0~127），是给音源的建议，不是身份。
所以同一份 `chords` 轨，换成钢琴、尼龙弦吉他、弦乐群、电钢琴，功能都还是"和声层"。
这一层尝试成本几乎为零 —— 在 Logic 里点一下。

---

## 四、代价（这些是真的，别忽略）

### 1. 同一功能要两个乐器时，会挤在一轨

想让钢琴和吉他**同时**弹和弦（分奏、加倍），它们属于同一功能层，会挤在 `chords` 里。
要么拆成 `chords_1` / `chords_2`，要么在 Logic 里把那条 MIDI 复制成两轨各自换音色。
本工程现在没有拆，需要时手工复制比加代码更划算。

### 2. 不反映演奏法

这是最实质的短板。一条 `chords` 轨只能有一种弹法：
现在是"三音同时按下的柱式和弦"，这个弹法给钢琴合理，给吉他就假
（吉他受把位限制、扫弦有弦间时差）。**换了音色不会换弹法。**

所以：想要"像真吉他"，需要的是新的 pattern（扫弦时序 + 把位约束），
不是新的轨、也不是新的音色。这也是上一轮讨论"为什么没有吉他"的真正结论。

### 3. 和混音总线不是一一对应

混音师习惯按总线分：鼓组 / 贝斯 / 键盘 / 吉他 / 人声 / 效果。
功能分层要再映射一次才能对上。这个映射在 Logic 里做（见下一节），不需要改代码。

## 五、其他分法，各自适合什么

| 分法 | 怎么分 | 适合 | 不适合 |
|---|---|---|---|
| **功能分层**（本工程） | 和声 / 低音 / 节奏 / 旋律 / 铺底 | 代码生成、参数要正交、快速迭代 | 真实编制、同功能多乐器 |
| 按乐器分 | 钢琴 / 吉他 / 弦乐 / 贝斯 / 鼓 | 真实编曲，每个乐器要有自己的演奏法 | 参数化生成（乐器一多组合爆炸） |
| 按混音总线（Stem） | 鼓组 / 贝斯 / 键盘 / 吉他 / 人声 / FX | 混音、交给混音师、影视交付 | 创作阶段（编制还没定） |
| 按音区 / 频段分 | 低频 / 中低 / 中高 / 高频 | 电子音乐（常说的"四层"）、频谱排布 | 有机乐器编制 |
| 按声部（SATB） | 女高 / 女低 / 男高 / 男低 | 合唱、传统和声写作 | 现代流行编曲 |

值得单独说一句**电子音乐的四层**：低频（底鼓 + 贝斯）、律动（鼓与打击）、
和声（和弦与铺底）、旋律与氛围。它和本工程的 8 层几乎是同一套东西的粗粒度版本 ——
如果你要判断"还缺什么"，用这四层扫一遍通常比逐轨检查快。

## 六、推荐用法：三层映射，别改生成层

结论：**保持现在的功能分层作为"生成层"，在 Logic 里叠加"编制层"和"混音层"。**
不要为了"想加一个乐器"去改代码，那会把正好的东西改乱。

```
生成层（代码）      8 个功能槽                    ← 参数、版本、可复现都在这里
      ↓ 换音源 / 复制成多条 / 需要新弹法时才加 pattern
编制层（Logic）     钢琴 + 吉他 + 弦乐群 + 贝斯 + 鼓组 + 打击 …
      ↓ 归并到总线
混音层（Logic）     鼓组 bus / 贝斯 bus / 键盘 bus / 吉他 bus / FX bus
```

具体做法：

1. **想换音色** → 直接改音源，不改代码。`chords` 换尼龙弦吉他、`pad` 换弦乐群。
2. **想让两个乐器同时弹和声** → 在 Logic 里复制 `chords` 那一轨，两轨各换音色、
   各自微调力度和音区（比如钢琴走中低、吉他走中高）。
3. **想要真正不同的弹法** → 这时才该动代码：新增 pattern（例如扫弦），
   成为新的功能槽。判断标准是"它能否用现有层的弹法表达"，不能才加。
4. **要交付给别人混音** → 按总线建 Track Stack，把 8 轨归到 4~5 条总线上。

**什么时候才真的该加一条轨**，只有两种情况：

- 它需要一套**不同的演奏法**（不是不同音色）
- 它需要**独立可调的第二个演奏线**（例如两把吉他分工）

否则加轨只是重复，重复的功能位不会让编曲更丰富，只会互相掩蔽。

## 七、自检：这套分法对这首歌还成不成立

一个很快的检验方法 —— **逐个静音**：

1. 全部静音，只留 `drums` + `bass`。还站得住吗？站不住 = 地基有问题，先修这个。
2. 加 `chords`。能听出和弦走向吗？听不出 = 排列或力度有问题。
3. 加 `lead`。旋律清楚吗？不清楚 = 有东西在抢（看体检的同音高冲突）。
4. 逐个加 `pad` / `arp` / `perc` / `counter`。每加一个问一句：**它解决了什么问题？**
   答不上来就该关掉。

这套顺序在 [02-听感问题定位.md](02-听感问题定位.md) 里展开成了具体的症状对照表。
