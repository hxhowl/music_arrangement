# 音乐创作知识库

写给**使用这套工程的人**。不是写给 AI 的执行规范 —— 那些在 `agents.md` 和 `.workbuddy/skills/` 里。

目的：把这套链路里隐含的音乐判断写明白，让你知道**为什么这么分、什么时候该动哪一层**，
而不是每次听完只知道"不对劲"却说不出改什么。

## 怎么读

| 文档 | 内容 | 什么时候读 |
|---|---|---|
| [01-分轨策略.md](01-分轨策略.md) | 为什么按功能分 8 层；好处、代价；其他分法对比 | 想加乐器、想改结构之前 |
| [02-听感问题定位.md](02-听感问题定位.md) | "糊 / 吵 / 空 / 平"分别是哪一层的问题，对应哪个参数 | 听完一版想改，但不知道动哪 |

## 这个知识库的边界

- 讲的是**本工程的取舍**，不是通用编曲教材。"按功能分轨"是为了让参数正交、
  让一句话能生成，不是行业唯一正确做法（对比见 01 的末节）。
- 参数名都对得上 `projects/<dir>/config.json` 和 `music/core/` 里的真实字段，可以边读边改。
- 它会随工程演进变化。与代码冲突时，以代码和 `README.md` 为准，然后回来改这份文档。

## 术语速查

| 词 | 在这里的意思 |
|---|---|
| 功能层 | 一个声音在歌里干的活（和声 / 低音 / 节奏 / 旋律 / 铺底），不是它是什么乐器 |
| 音色 | 实际发声的乐器或合成器。同一份 MIDI 换音源 = 换音色，功能不变 |
| 演奏法 | 音符怎么被弹出来：扫弦、连弓、断奏、切分。由 pattern 决定 |
| 声部 | 一条独立的旋律线。同时能听清几条线，决定编曲的"厚度" |
| 音区 | 一个声音落在多高多低。两轨音区重叠是正常的；**同音高同时响**才是问题 |
| 铺底 | 长音持续、把和声粘住的那层。通常听不出旋律，但抽掉就空 |
| 切分 | 重音不落在正拍上，制造"往前推"的感觉 |
| 声部进行 | 和弦换的时候，每个音尽量走最近的音，不要整块平移（本工程的 voice leading） |
