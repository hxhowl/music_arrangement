# decisions.md — demo

每个有听感后果的改动记一条：改了什么 / 为什么 / 预期听到什么变化。
版本号对应 `music/output/demo-vN.mid`，同目录 `demo-vN.config.json` 是当时的参数快照。

## v1 — 2026-10-28 20:58（原始实现，保留作对照）

元宝生成的初版，未修改。已知问题见 `docs/code-review-2026-10-28.md`。

## v2 — 2026-10-28 22:16（修 P0，音乐内容基本未变）

- 和弦数据改为只有 `core.theory` 一份：此前改 `theory.py` 和弦不跟随，会与贝斯错位。
- 贝斯根音由和弦名推导并折进 A1~G#2：v1 的 `F#m` 实际弹的是 A3（和弦三音），

- PPQ 220 → 960。
- **预期听感**：贝斯从含糊的中频轰鸣变成正常低频走向；其余基本同 v1。

## v3 — 2026-10-28 22:34（中间态，已被 v4 取代）

首次引入段落编排与 pad 轨。lead 仍是写死半音动机，在 A 大三和弦上取到 C5（小三度），
与 C# 打架；且 `i % 2` 跳过与 4 小节进行的奇偶周期相同，导致 D / E 两个和弦整段没有旋律。
**不要用这一版**。

## v4 — 2026-10-28 22:40（段落编排成型）

- 新增 `music/core/arrange.py`：每段独立决定轨开关、鼓密度、力度缩放。
  - intro：只有 chords + pad，力度 0.70（原来第一拍就是满编鼓，没有留白）
  - verse：加 bass + 半拍鼓，0.85
  - chorus：满编鼓 + 进吊镲 + 进 lead，1.00
  - outro：回到 chords + pad，0.65（原来 outro 4 小节完全空白）
- 新增 `music/patterns/pad.py`：开放五度堆叠（8 度/12 度/2 个 8 度），不叠三音，避免中频糊。
- 鼓：半拍 / 满编 / 只有踩镲 三档，四小节一次桶鼓过门，段落起点吊镲，正拍重反拍轻。
- lead 改为**按和弦音级取音**（根-三-五-三 / 根-五-八-五），每 4 小节留一小节双长音呼吸。
- 配置下沉到 `projects/demo/config.json`，每版写参数快照。
- **预期听感**：有了真正的段落推进；副歌进入有吊镲和过门；旋律落在和弦上，E 和弦不再空。

## v5 — 2026-10-28 23:10（和弦改为级数推导 + 风格库）

- 和弦进行从"全局绝对和弦名"改成 **`key` + 级数**：`F#m` + `i-VI-III-VII` → `F#m - D - A - E`。
  和弦仍在 `config.json` 里（`key` / `progression`），换歌不再污染其它项目。
- 新增 `music/core/styles.py` 风格库（cinematic / pop / lofi / playful），
  同一份段落编排在不同风格下得到完全不同的律动。
- pattern 改为数据驱动：`build(inst, ctx)`，不再有写死的 `PROGRESSION` / `MOTIF` / `base_roots`。
- 和弦名按调号拼写（D 小调的 VI 级是 `Bb`，不是 `A#`）。
- 本曲切到 `cinematic`：和弦长音铺满、贝斯全音符、鼓只做心跳、旋律两音大跳。
- **预期听感**：比 v4 更空、更慢、更"配乐"；动态落差比 v4 小，因为鼓是心跳而不是满编。

## 未做 / 已知局限

- `swing` 未实现（写非 0 会直接报错）
- 只支持 4/4
- 和弦全部原位三和弦，没有转位与 voice leading
- `arp` 轨未实现

## v5 之后：生成参数扩展（产物未变）

- `config.json` 新增 `seed` / `style_tweaks` / `arrange` 三个字段。
- 意义：以前"副歌鼓太满""贝斯太吵"只能改全局库，会连累所有项目；
  现在写进本项目 config 即可，**改动只作用于这一首**。
- `seed > 0` 可出"同一编曲的不同演奏"（力度扰动、鼓的装饰音、旋律短语起点）。
- 本曲的 `seed` 保持 0，`style_tweaks` / `arrange` 为空 —— 所以 `demo-v5.mid`
  与改动前字节完全一致（已用 sha256 对比确认）。

## v5 之后：段落级风格 + 清掉写死的创作参数（产物未变）

- `config.json` 的 `arrange.<段>.style` 可以让某一段换风格，整首主基调仍由 `style` 决定。
  实测：主歌 cinematic 不动，副歌换 playful 后和弦从 2.38s 长音变 0.84s 断奏、
  贝斯 4→16 音、鼓 20→53 音，主歌一个音符没变。
- 原先写死在代码里的创作参数移入 `styles.py`：
  `crash` / `fill` 策略（原来写死 `section == "chorus"`）、
  旋律音区、过门间隔（`fill_every`）、装饰音概率与力度（`ghost`）、
  旋律力度（`lead.velocity`）、humanize 强度（`humanize`）。
- 本曲没用到任何新字段，`demo-v5.mid` 与改动前字节一致（sha256 642ca65c…）。

## v6 — 2026-10-29（修 pad/旋律同音冲突 + 声部进行 + 扩到 7 轨）

- **修 bug**：lead 与 pad 原来有 10 处「同一时刻同一个音高」，同频叠置会互相抵消，
  旋律轮廓变糊。现在 pad 会跳过旋律正在响的音高，并在有旋律的段落压到 0.72。
  体检新增这项检查（只查涉及旋律的冲突；伴奏之间同音加倍是正常配器手法）。
- **和弦改用 voice leading**：每个声部走最近的八度，不再每小节原位硬跳。
  和弦音域从 D3~E4（跨 15 个半音）收窄到 E3~D4（跨 11 个），内声部移动明显变小。
- **新增 2 条轨**：`perc`（沙锤，撑律动）、`arp`（琶音，填中高频）。
  两轨都按段落开关：perc 只在主歌/副歌，arp 在 intro/副歌/bridge。
- **lofi 启用七和弦**：`chords.seventh=True`，和弦名变成 Am7/Fmaj7 之类。
- **预期听感**：旋律更清楚；和弦连接更顺；中高频不再空；律动更"活"。
- 回归：`pytest` 59 项通过；体检通过；确定性与多 take 未受影响。

## v7 — 2026-10-29（和声节奏 + swing + 副旋律 + 音效清单）

- **和声节奏**：`chords.beats` 进风格库。cinematic 默认 8 拍（两小节一个和弦），
  所以这版的和弦变化比 v6 慢一半 —— F#m 撑两小节、D 撑两小节。
  预期听感：更"铺得开"，不再每小节换一次色。
- **swing 已实现**：config 写 `swing` 即可，0 = 直拍。本曲没开（cinematic 心跳鼓摇起来会怪）。
- **新增第 8 轨 `counter`（副旋律）**：只在主旋律空档出声，音区压在 lead 之下。
  本曲主歌没有 lead，所以 counter 出现在主歌（第 5~12 小节），副歌留白给主旋律。
- **音效时间点**：新产物 `demo-v7.cues.md`，列出 riser / impact 的小节位置。
  音效是采样，不做成 MIDI 轨。
- 预期听感：和声更宽、主歌多一条低音答句、副歌更干净（没有第二条线抢旋律）。

## v8 — 2026-10-29（换编制：preset=cinematic）

- **只改了一件事**：`config.json` 加 `"preset": "cinematic"`。
  音色从"钢琴 / 指弹贝斯 / 合成琶音 / 方波 / 大提琴 / 合成铺底"换成
  "弦乐群 / 立式贝斯 / 竖琴 / 小提琴 / 圆号 / 弦乐群"。
- 音符层面只有 `pad` 变了（长音 1.0→0.99 小节、力度 30→29），因为弦乐群自带
  `hold=0.99` / `duck=0.70`；`chords` 也换成弦乐群但音符没动 ——
  cinematic 风格本来就把和弦拉得很长，这个需求已经满足了。
- 预期听感：整体更"电影感"、更连贯；但**结构没变** —— 如果换完还是那个味儿，
  问题在段落/律动/和声节奏，不在音色。
- 回归：pytest 全绿；体检通过。

## v9 — 2026-10-30（副歌加一层上方对位）

- **副歌开 `counter`，并把它放到主旋律上方**：
  `arrange.chorus = {"counter": true, "counter_voice": "high"}`。
  这一版的意义在于验证"分声部"：`low` 只在主旋律空档回话（原来的写法），
  `high` 允许和主旋律同时响，位置跟着旋律走、落在它上方 3~10 个半音。
  本曲配的是圆号，正好适合这个音区。
- **实测**：`counter` 从 16 个音（只在主歌）变成 32 个音，音域 G#4~E6；
  与主旋律同时响的 16 处音程全是 5/7/8/9 个半音（四度到六度），没有同度。
- **顺带修了两个 bug**：
  1. 副旋律取音允许越出音区窗口 12 个半音，而"按八度折回"对不足八度的越界无效，
     会漏出窗口外的音（高位声部曾漏到 93）。现在取音严格限制在窗口内。
  2. `occupied`（主旋律占用的音高）用的是段落内小节号，但字典是全曲共享的 ——
     主歌第 1 小节占的音高会让副歌第 1 小节的 pad / arp 白让开。
     改用绝对小节号后，同一份编排下 `pad` 从 50 个音变成 59 个（9 个是被误压掉的）。
- 预期听感：副歌上方多一条长音线，厚度上来但不抢旋律；铺底比上一版更满。
- 回归：pytest 120 项通过；体检通过，无同音高冲突提示。
